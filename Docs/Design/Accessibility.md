NEXUS — Accessibility Principles

1. Accessibility Goal

Accessibility is treated as a product architecture requirement rather than a visual polish stage.

---

2. Keyboard

All major actions should be accessible using the keyboard.

Important shortcuts include:

⌘/Ctrl + K     Command Palette
Esc            Close surface
Enter          Confirm
Space          Activate
Tab            Navigate

---

3. Focus

Keyboard focus must always be visually apparent.

Focus indicators should not depend solely on color.

---

4. Contrast

Text and interactive elements must maintain appropriate contrast.

---

5. Color

Color cannot be the sole communication mechanism.

For example:

Instead of:

🔴 At Risk

Use:

"⚠ At Risk"

with appropriate semantic styling.

---

6. Motion

Provide support for reduced-motion preferences.

---

7. Screen Readers

Interactive controls should have meaningful accessible names.

Decorative visual elements should not create unnecessary screen-reader noise.

---

8. Touch

Interactive targets should be appropriately sized for touch interaction.

---

9. Cognitive Accessibility

NEXUS should minimize:

- unnecessary notifications,
- ambiguous actions,
- excessive simultaneous information,
- unpredictable behavior.

Clear hierarchy is an accessibility feature.
